# コーディングエージェントへの指示

以下のルール全てに厳格に従う。ただしセッション内でユーザーから同じルールに関する指示がある場合はそちらを優先する。

## 会話のルール

- 常に日本語で会話する
- 平易な文章になるよう心がける
- 自然な日本語の文章にする。助詞は特に重要なので使い方に気をつける

## 実装のルール

- その方がより良い実装になるのであれば、既存実装やそこでの判断は無視する
- YAGNI原則を強く意識する

## 作業のルール

- GitHub のリポジトリが見たいときは、まず先に `~/ghq` 以下を探す
- `ghq` になければ `ghq get` で clone する

## コミットメッセージのルール

- 英語で書く
- 変更の目的が分かる簡単な一文にする
- コミットには Co-Author をつける

## Pull Request のルール

- PR のタイトルは英語、説明文は日本語で書く
- PR の説明文は変更の目的が分かる簡単なものにする

## ファイル変更後のルール

ファイルを変更した後、以下フローを順番に実行する。

1. プロジェクトで指定された検証手順があり、未実施であれば実施する
2. 現状の変更差分を全て確認し、過去の経緯や無意味になった記述(実装、コード、テスト含む)を削除する
3. このブランチに紐づく PR がある場合は、必要に応じてタイトルと説明文を更新する
